# 进展台账与大纲格式

## 任务定义卡

在列结果前，用一张卡片把研究任务解释给不了解项目代号的科研听众。没有可靠证据的字段写 `Unknown`。

| 字段 | 内容 |
|---|---|
| 研究问题 | 本周期试图回答的具体问题 |
| 输入 | 模型或分析真正获得的信息，包括可选条件 |
| 输出 | 需要预测、重建、分类或解释的对象 |
| 时间/分析范围 | 历史窗口、预测区间、帧级/序列级或其他边界 |
| 数据与测量 | 数据集、受试者/场景、传感器或标注来源 |
| 成功标准 | 本周期用什么指标或证据改变路线判断 |
| 不可声称内容 | 测量能力、协议或证据尚不能支持的结论 |

## 实验口径映射

主要结果进入汇报主线前，先建立下表。口径不同的结果保留为独立行并标明不可直接比较。

| 结果 ID | 实验角色 | 数据/受试者 | 切分或 fold | 样本与统计单位 | 比较双方 | 指标含义与方向 | 证据 | 可比性说明 |
|---|---|---|---|---|---|---|---|---|

## 具体进展台账

每项进展建议使用以下字段；没有信息的字段标为 `Unknown`，不要猜测。

| 字段 | 内容 |
|---|---|
| ID | 稳定短编号，如 `P01` |
| 日期 | 证据发生或产出的日期 |
| 类别 | baseline、motivation/data、analysis、route、application 或项目自定义类别 |
| 进展 | 一句话说明完成了什么 |
| 科研意义 | 它回答了哪个问题或改变了哪个判断 |
| 状态标签 | Observed / Derived / Hypothesis / Unknown |
| 核心证据 | 文件路径、行号/函数、命令、run/artifact/commit ID |
| 结果与限制 | 数字、现象、适用范围、不可声称内容 |
| 后续动作 | 下一实验、补证据、实现或复核 |
| 待讨论 | 需要导师/团队决定的具体问题 |

## 聚类汇总

每个汇报大点写清：

1. 核心结论或问题；
2. 由哪些台账 ID 支撑；
3. 最适合的证据形态（曲线、表格、案例图、路线矩阵或一句话）；
4. 重点级别与理由；
5. 建议讲述时长；
6. 预期听众追问与备用证据。

## 汇报大纲

| 顺序 | 章节 / 页面任务 | 一句话 takeaway | 证据 | 权重 | 建议页数 |
|---|---|---|---|---|---|

结尾单列：

- 本周期得到的最可靠结论；
- 尚不能下的结论；
- 候选路线及选择标准；
- 需要现场确认的 1–3 个问题；
- 下一周期最小可验证计划。
